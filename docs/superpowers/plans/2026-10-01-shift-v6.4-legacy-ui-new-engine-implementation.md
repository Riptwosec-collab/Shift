# Shift Command Center v6.4 — Legacy UI + New Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the pre-v6.3 Shift Command Center visual shell shown in Build `#ee755b37` and add the requested operational engine/features without removing, replacing, or redesigning any legacy UI surface.

**Architecture:** Treat commit `e6d8e05da1250b86e5f905dfd843b7e3cace2579` as the repository-backed legacy visual shell and the approved screenshot of Build `#ee755b37` as the visible layout authority. Restore that shell first, then progressively route it through shared state, cache, lazy view mounting, and pure feature models. Production remains a standalone `index.html` compatible with the current Cloudflare direct-deploy setup.

**Tech Stack:** Static HTML/CSS/vanilla JavaScript, Node.js test runner, existing `scripts/build.mjs`, Wrangler/Cloudflare Static Assets configuration.

**Spec:** `docs/superpowers/specs/2026-10-01-shift-v6.4-legacy-ui-new-engine-design.md`

## Global Constraints

- Build `#ee755b37` screenshot is the visible target; if it differs from repository-backed pre-v6.3 source, the screenshot wins for visible layout and appearance.
- Repository-backed visual baseline: commit `e6d8e05da1250b86e5f905dfd843b7e3cace2579`.
- Additive-only migration: no legacy visual component may be removed, replaced, or simplified as part of feature integration.
- Preserve exact employee names and exact October 2026 31-day schedule strings.
- User-facing `O` always displays as `OFF`.
- D = red, N = blue, OFF = green.
- Default visual mode on every reload is `BALANCED`; no mode/view/date/person/palette persistence.
- HIGH preserves the full legacy appearance and motion; BALANCED/ECO reduce runtime cost without hiding structural graphics.
- No `document.write()`, `DecompressionStream`, runtime gzip handoff, or global body-scanning MutationObserver.
- Production output remains a standalone `index.html` with no external runtime dependency.
- Cloudflare direct deploy must continue to publish only tracked production `index.html`; do not make Cloudflare depend on `dist/`.

## Review Focus

- **Visual regression:** legacy command bar, hero cyber scene, D/N/OFF cards, timeline, 3 roster panels, Insights, Team Network, and Month Matrix remain present and in the same hierarchy. Covered by Task 2.
- **Hidden eager work:** unopened Daily/Person/Month/Analytics views perform no full render during startup. Covered by Task 4.
- **Boundary dates:** day 1/day 31 comparison/transition logic never wraps into another month. Covered by Task 5.
- **Mode degradation:** BALANCED/ECO reduce motion/blur but do not remove legacy graphic structures or mutate schedule data. Covered by Task 3.
- **Cloudflare regression:** `npx wrangler deploy` with Build command `None` does not depend on `dist/` and does not upload `node_modules`. Covered by Task 10.

## Implementation Order Rationale

1. Lock visual/data invariants.
2. Restore the actual legacy shell before integrating new behavior.
3. Centralize state/cache/modes without forcing renderer redesign.
4. Establish lazy mounting using temporary secondary-view adapters.
5. Replace those adapters one feature/view at a time with legacy-specific renderers.
6. Add cross-view synchronization only after all participating interfaces exist.
7. Add Palette/Mobile last because they orchestrate existing navigation/state.
8. Finish with browser, performance, and Cloudflare regression gates.

## Completion Criteria

v6.4 is complete only when:

- HIGH mode retains the approved Build `#ee755b37` visual identity and every listed legacy component.
- No legacy visual component was removed to make room for a new feature.
- Lazy Render + Cache, HIGH/BALANCED/ECO, expanded Daily, Team Network 2.0, Staffing Risk, Workload Balance, Interactive Timeline, Command Palette, and Mobile UX are present.
- BALANCED/ECO reduce runtime cost through behavior/effect intensity rather than structural content removal.
- Exact employee/schedule tests pass.
- Lazy-render tests prove unopened views do no full render at startup.
- Daily boundary, Risk, Network, Analytics, Command Palette, and Mobile tests pass.
- Production `index.html` is standalone and its inline JavaScript parses.
- Cloudflare remains compatible with Build command `None` and `npx wrangler deploy`.
- Final `npm test` passes with zero failures after production rebuild.
