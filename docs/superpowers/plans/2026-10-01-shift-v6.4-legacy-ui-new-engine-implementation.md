# Shift Command Center v6.4 — Legacy UI + New Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the pre-v6.3 Shift Command Center visual shell shown in Build `#ee755b37` and add the v6.3 operational engine/features without removing or redesigning any legacy UI surface.

**Architecture:** Treat commit `e6d8e05da1250b86e5f905dfd843b7e3cace2579` as the repository-backed legacy visual shell and the approved screenshot of Build `#ee755b37` as the visible layout authority. Keep the legacy DOM/CSS component family intact, then feed it through modular state/cache/model code and additive detail surfaces. Production remains a standalone `index.html` deployed by the existing Cloudflare direct-deploy setup.

**Tech Stack:** Static HTML/CSS/vanilla JavaScript, Node.js test runner, existing `scripts/build.mjs`, Wrangler/Cloudflare Static Assets configuration.

**Spec:** `docs/superpowers/specs/2026-10-01-shift-v6.4-legacy-ui-new-engine-design.md`

## Global Constraints

- Build `#ee755b37` screenshot is the visible target; if it differs from repository-backed pre-v6.3 source, the screenshot wins for visible layout and appearance.
- Repository-backed visual baseline: commit `e6d8e05da1250b86e5f905dfd843b7e3cace2579`.
- Additive-only migration: no legacy visual component may be removed, replaced, or simplified as part of feature integration.
- Preserve exact employee names and exact October 2026 31-day schedule strings.
- User-facing `O` always displays as `OFF`.
- D = red, N = blue, OFF = green.
- Default visual mode on every reload is `BALANCED`; no mode/view/date/person/palette persistence.
- HIGH preserves the full legacy appearance and motion; BALANCED/ECO reduce runtime cost without hiding structural graphics.
- No `document.write()`, `DecompressionStream`, runtime gzip handoff, or global body-scanning MutationObserver.
- Production output remains a standalone `index.html` with no external runtime dependency.
- Cloudflare direct deploy must continue to publish only the tracked production `index.html`; do not reintroduce `dist/` as a required Cloudflare build artifact.

## Review Focus

- **Visual regression:** legacy command bar, hero cyber scene, D/N/OFF cards, timeline, 3 roster panels, Insights, Team Network, and Month Matrix must all remain present and in the same hierarchy after engine integration. Pin in Task 2.
- **Hidden eager work:** no unopened Daily/Person/Month/Analytics view may perform full rendering during startup. Pin in Task 4.
- **Boundary dates:** day 1/day 31 comparisons and transitions must not wrap into another month. Pin in Task 5.
- **Mode degradation:** BALANCED/ECO may reduce motion/blur but must not remove legacy graphic structures or mutate schedule data. Pin in Task 3.
- **Cloudflare regression:** `npx wrangler deploy` with Build command `None` must not depend on `dist/` and must exclude `node_modules`. Pin in Task 10.

## Implementation Order Rationale

1. Lock visual/data invariants before touching the shell.
2. Restore the old shell before integrating feature logic so every later task is tested against the right UI.
3. Centralize state/cache/performance before adding view-specific features.
4. Enforce lazy mounting before new views grow heavier.
5. Add Daily/Risk and Network independently because both consume the shared cache but not each other.
6. Add Analytics/Person and shared timeline synchronization after model contracts are stable.
7. Add Palette/Mobile last because they orchestrate existing state/navigation rather than define it.
8. Finish with Cloudflare and browser-level regression gates before shipping.

## Completion Criteria

v6.4 is complete only when all of the following are true:

- HIGH mode visually retains the approved legacy Build `#ee755b37` identity and all listed legacy components.
- No existing visual component was removed to make room for a new feature.
- All requested P0/P1/P2 features are available.
- BALANCED/ECO improve runtime cost by reducing behavior, not structural content.
- Exact employee/schedule tests pass.
- Lazy-render tests prove unopened views do no full render at startup.
- Daily boundary, Risk, Network, Analytics, Command Palette, and Mobile tests pass.
- Production `index.html` is standalone and JavaScript parses successfully.
- Cloudflare direct deploy remains compatible with Build command `None` and `npx wrangler deploy`.
- `npm test` passes with zero failures after the final production build.
