# Shift Command Center v6.4 — Legacy UI + New Engine Design

Date: 2026-10-01
Repository: `Riptwosec-collab/Shift`
Target branch: `main`

## 1. Goal

Build v6.4 by restoring the pre-v6.3 visual shell and adding the newer operational features behind and around that shell without reducing, replacing, or redesigning the existing interface.

The user-selected visual reference is Build `#ee755b37` shown in the approved screenshot. That identifier is not resolvable as a Git commit in this repository, so the implementation baseline is defined by two sources together:

1. The approved screenshot of Build `#ee755b37`.
2. The closest repository-backed pre-v6.3 implementation at commit `e6d8e05da1250b86e5f905dfd843b7e3cace2579` (`Optimize dashboard performance and loader v6.2.1`).

If the screenshot and pre-v6.3 source differ, the screenshot wins for visible layout and appearance, while the repository source supplies the implementation structure and behavior.

## 2. Primary constraint: additive-only visual migration

v6.4 must preserve the legacy visual system as the primary product UI.

The following legacy visual elements are invariants and must remain present unless the user explicitly requests a later change:

- Sticky top command bar.
- Original brand mark and `Shift Command Center` header treatment.
- Original Overview/Daily/Person/Month/Analytics navigation styling.
- LIVE status pill and system controls.
- Cyberpunk navy/cyan/blue/purple palette.
- HUD panel borders, corner treatments, glow, blur, and depth.
- Hero stage with cyber city / bars / grid / scan-beam atmosphere.
- Original D/N/OFF metric cards and their visual hierarchy.
- Horizontal October timeline with all days.
- Three main roster panels for Day, Night, and OFF.
- Insights panel with existing tabs and visual proportions.
- Team Network card in the original lower-left position.
- Month Matrix card in the original lower-right position.
- Existing hover/focus treatments, ambient backgrounds, and high-fidelity motion.
- Existing responsive identity on tablet/mobile.

New functions may add badges, secondary rows, tooltips, drawers, overlays, drill-down details, or hidden-on-demand panels, but they must not replace the legacy components with a different component family.

## 3. Explicit non-goals

v6.4 must not:

- Use the simplified v6.3/v6.3.4 card layout as the primary UI.
- Remove legacy graphic elements in order to improve performance.
- Replace the hero scene with a plain card.
- Replace roster panels with generic lists.
- Replace Team Network with a new visual language.
- Replace Month Matrix with a generic table-only presentation.
- Change employee names.
- Change any October 2026 schedule character.
- Persist last view, selected day, selected person, visual mode, or command-palette history across reloads.
- Reintroduce `document.write()`, runtime gzip handoff, or `DecompressionStream`.
- Break the current Cloudflare direct-deploy contract.

## 4. Data invariants

The canonical schedule remains the same 10 employees and 31-day strings already locked by existing tests.

Internal status representation remains:

- `D` = Day
- `N` = Night
- `O` = Off

User-facing status remains:

- D = red
- N = blue
- OFF = green

All user-facing off-duty labels must display `OFF`, not `O`.

Responsibilities:

- `legacy-ui.css`: preserved legacy visual system plus additive feature styles.

## 7. P0 — Lazy Render + Cache

### 7.1 Startup

At startup, only work required for the visible Overview is performed synchronously.

Allowed before first interactive frame:

- Parse static roster data.
- Build lightweight daily count lookup.
- Initialize app state.
- Bind global navigation and command shortcuts.
- Render/update visible Overview content.

Deferred until needed:

- Full Daily details.
- Person detail calendar.
- Full Month heatmap logic beyond the existing Overview snapshot.
- Analytics workload table.
- Full Team Network relationship detail calculations if not already cached cheaply.

### 7.2 Cache

Cache once per page load:

- D/N/OFF counts per day.
- Working count and coverage per day.
- Per-person D/N/OFF totals.
- Longest work streak.
- Longest night streak.
- Pairwise same-shift counts.
- Pairwise same-D counts.
- Pairwise same-N counts.
- Handoff counts.
- Normalized relationship strengths.
- Team averages.
- Busiest and least-staffed days.

No cache entry may contain mutable UI selection state.

## 8. P0 — HIGH / BALANCED / ECO

Performance modes change rendering cost, not component presence.

### HIGH

HIGH is the exact legacy visual target.

- All original ambient layers remain visible.
- Cyber city / bars / floor grid remain visible.
- Original scan beam and decorative motion remain enabled.
- Original hero and HUD glow remain at full intensity.
- Original Team Network motion/glow remains enabled.
- Original panel blur and hover effects remain enabled.

HIGH is the visual reference mode for regression review.

### BALANCED

BALANCED keeps every legacy visual element but lowers runtime cost.

- Reduce animation frequency or duration on nonessential loops.
- Throttle pointer/parallax work through `requestAnimationFrame`.
- Pause offscreen decorative animation.
- Reduce large fixed-layer blur cost where visually indistinguishable.
- Reduce Network pulse frequency.

No element is removed or hidden simply because BALANCED is active.

### ECO

ECO keeps the same layout, colors, labels, city/graph structures, and component hierarchy, but makes most decoration static.

- Stop continuous parallax.
- Stop scan/pulse loops.
- Reduce dynamic blur/glow updates.
- Keep all structural graphics visible as static artwork.
- Use shorter transitions.

No element is deleted from the DOM for ECO.

Default after every reload: `BALANCED`.

No mode persistence.

## 9. P0 — Daily View expansion

The legacy Daily page remains visually intact and receives additive operational details.

Add:

- D/N/OFF/Coverage summary.
- Previous-day and next-day comparison.
- D/N/OFF/working/coverage deltas.
- Shift transitions (`D→N`, `N→OFF`, `OFF→D`, etc.).
- Current working streak.
- Current night streak.
- Relevant staffing-risk signals.

New Daily information should appear in existing HUD styling below or beside the current Daily content, not replace existing cards.

Boundary behavior:

- Day 1 previous = unavailable.
- Day 31 next = unavailable.
- Never wrap across months.

## 10. P1 — Team Network 2.0

The visible Team Network must keep the legacy circular/HUD presentation.

Enhance its data model with:

- `sameShift`
- `sameD`
- `sameN`
- `handoff`
- `strength`
- `topTeammate`

Default strength formula:

```text
raw = sameShift * 2 + handoff
strength = round(raw / maxPairRaw * 100)
```

Zero-max protection returns `0`.

Interaction:

- Clicking a node changes the center person.
- Existing graph stays in the same panel and style.
- Hover/focus/tap reveals detailed relationship metrics.
- Stronger relationships may use thicker/brighter existing-style edges.
- Limit visible outer nodes responsively to avoid overflow.
- Full relation details remain accessible in a compact detail area or drawer.

Desktop max visible outer nodes: 6.
Tablet: 5.
Mobile: 4.

## 11. P1 — Staffing Risk

Staffing Risk is informational only and must never alter the schedule.

Default thresholds:

- `LOW_STAFFING`: working < 6
- `LOW_NIGHT_COVERAGE`: N < 2
- `CONSECUTIVE_WORK`: 3+ working days
- `LONG_NIGHT_STREAK`: 3+ N shifts
- `D_N_IMBALANCE`: abs(D-N) >= 3
- `HIGH_OFF_COUNT`: OFF >= 5

UI integration:

- Primary location: existing Insights `แจ้งเตือน` tab.
- Secondary location: Daily details for the selected date.
- Use existing HUD colors, badges, iconography, spacing, and typography.
- Do not add a visually unrelated warning component family.

## 16. Loader

The legacy-style loader remains approximately 3 seconds as previously approved.

Contract:

- Target: 3000 ms.
- Hard exit: 3600 ms maximum.
- Never wait on Analytics, Network details, or secondary view rendering.
- Keep the cyber/HUD visual direction.
- Loader animation itself must stay smooth and avoid heavy main-thread work.

During the loader, defer expensive feature initialization so the loader does not stutter.

## 18. Error handling

The dashboard must fail soft.

- Legacy Overview must still render if an enhancement model throws.
- Network enhancement failure falls back to the legacy Network display.
- Analytics enhancement failure leaves the legacy analytics view usable.
- Missing optional DOM target skips only that enhancement.
- Loader always exits by the hard timeout.
- No full-body MutationObserver loops.
- No repeated global DOM scans for OFF normalization.

## 19. Deployment contract

Current Cloudflare direct deploy must remain compatible.

Expected Cloudflare command:

```text
npx wrangler deploy
```

The repository must continue to prevent `node_modules` or other development files from becoming uploaded assets.

Production remains a standalone `index.html` suitable for the current direct-deploy configuration.

v6.4 must not require the Cloudflare dashboard Build command to change from its current direct-deploy behavior unless the user explicitly approves that deployment change later.

### 20.6 Production tests

Verify:

- Standalone `index.html` has no unresolved build placeholders.
- JavaScript parses without syntax error.
- No `${...}` template expression is accidentally rendered as text.
- No `document.write()`.
- No `DecompressionStream`.
- Loader exits by 3600 ms.
- Cloudflare asset allowlist remains valid.

## 21. Release strategy

Do not replace `main` with an unverified visual merge.

Recommended release flow:

1. Create an isolated v6.4 branch/workspace.
2. Restore the pre-v6.3 legacy visual shell from the repository-backed baseline.
3. Lock visual landmarks and schedule data with tests.
4. Integrate new engine features incrementally.
5. Build standalone production `index.html`.
6. Run unit, integration, data-integrity, visual-landmark, and deployment-contract checks.
7. Compare HIGH mode manually against the approved screenshot.
8. Merge/publish only after the verification suite passes.
