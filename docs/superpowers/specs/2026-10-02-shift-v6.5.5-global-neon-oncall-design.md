# Shift v6.5.5 — Global Neon Design System + Individual Engineer Oncall

## Goal
Upgrade the existing Shift v6.5.4 interface into a cohesive, colorful, futuristic cyber command-center across the entire application, while preserving all current data, features, TH/EN localization, and HIGH/BALANCED/ECO performance modes. The Engineer Oncall view must become individual-centric: show who is on call today, who is next, and present the monthly schedule as a per-person x date matrix matching the supplied reference layout.

## Constraints
- Preserve existing application behavior and data.
- Preserve TH/EN switching.
- Preserve HIGH/BALANCED/ECO behavior.
- Preserve current views, navigation, charts, roster data, and on-call schedule.
- Do not remove existing Overview / Matrix / Timeline modes.
- Keep the generated single-file `index.html` production artifact flow intact.
- Prefer additive v6.5.5 CSS/JS layers over invasive rewrites.
- Mobile must remain usable; horizontally dense on-call matrices may scroll.
- Animations must degrade in ECO/reduced-motion mode.

## Architecture

### 1. Global visual layer
Add a dedicated v6.5.5 theme layer on top of the existing v6.5.4 CSS. The layer defines shared design tokens and consistent surfaces for all major panels, cards, tables, controls, tabs, chips, navigation, loader states, and overlays.

The global palette uses deep navy/black foundations with cyan, electric blue, violet, magenta, emerald, and amber accents. Color is applied by semantic role rather than per-page ad-hoc rules. The background keeps the current cyber-space concept but becomes richer through restrained aurora, luminous grid, scanlines, edge glow, and depth overlays.

The global styling layer must target existing shared classes such as command bars, HUD panels, insights/network/month/roster surfaces, navigation, buttons, cards, tables, and view containers so that all existing pages receive the upgraded visual language.

### 2. Performance-safe effects
HIGH may use animated aurora/grid glow and stronger blur/glass effects. BALANCED uses the same visual structure with reduced animation frequency and blur. ECO and `prefers-reduced-motion` disable nonessential continuous motion and reduce expensive blur/shadow intensity.

### 3. Engineer Oncall individual model
Reuse the current on-call schedule source and matrix model. Do not duplicate or hand-copy schedule data.

The rendering layer derives:
- current on-call assignment(s) for the selected/current date,
- next scheduled assignment,
- per-engineer total days,
- per-engineer active dates for the selected month,
- selected date details.

The UI treats each engineer as an individual lane, not as anonymous schedule rows.

### 4. Engineer Oncall layout
The Engineer Oncall view retains Overview / Matrix / Timeline navigation, but the default Overview is upgraded into four zones:

1. **Today / Next hero** — prominent individual cards for today's on-call engineer and the next engineer. Cards show person name, status, date range, and handoff direction. If multiple people are assigned on a date, render all assigned individuals rather than collapsing them.
2. **Individual engineer strip** — one compact card per engineer with identity accent, total on-call days, current/next state, and quick focus behavior.
3. **Per-person monthly duty matrix** — rows are engineers, columns are dates 1–31. Active cells display `OC`; empty cells stay visually quiet. Current date, selected date, current engineer, and next engineer receive distinct states. The left identity column remains sticky while the matrix scrolls horizontally.
4. **Selected-day detail panel** — selecting a matrix date/cell shows that date, assigned engineer(s), their active period, and the following handoff.

The dedicated Matrix tab keeps the dense matrix as the primary view and gains the same interaction/state treatment. Timeline continues to show handoff sequence.

## Interaction
- Clicking an engineer card focuses/highlights that engineer's matrix row.
- Clicking a date header selects that date.
- Clicking an active `OC` cell selects both the engineer and date.
- The selected-day panel updates without navigation.
- When the selected month is the current month, initial selection is today; otherwise select the first scheduled date in that month.
- Horizontal matrix scrolling is smooth and touch-friendly.
- Matrix headers and the engineer-name column are sticky where practical.

## Visual states
Each engineer receives a stable accent class from the existing person mapping. Current on-call uses a live emerald/cyan treatment; next handoff uses violet/blue; selected states use a brighter edge and inner glow. Empty matrix cells remain dark enough that `OC` blocks are immediately readable.

## Responsive behavior
- Desktop: full hero, individual cards, matrix, and detail panel.
- Tablet: hero cards stack if needed; matrix remains horizontally scrollable.
- Mobile: Today/Next cards become a vertical stack, individual strip becomes horizontal snap-scrolling, matrix uses a sticky identity column and touch horizontal scrolling, detail panel moves below the matrix.

## Accessibility
- Preserve readable text contrast.
- Use visible focus states for buttons, tabs, date headers, and matrix cells.
- Matrix cells include useful `aria-label`/`title` text.
- Do not rely on color alone for live/next/selected states.
- Respect `prefers-reduced-motion`.
